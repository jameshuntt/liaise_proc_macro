# Changelog

## 0.1.3 (2026-10-15)

0.1.3 is the collector. A proc macro can now go through all of its checks, collect each error from each part, and hard fail once at the end with all of them, instead of stopping at the first `?`. `ensure!`, `SynBuffer::absorb`, `SynBuffer::finish_with` and `collect_all` are the pieces, and `liaise_codes!` now catches a duplicate code under `cargo check` too. Also added CI that tests on stable and 1.85 and publishes from main.

### the collector

- there was no short way to check one rule into a `SynBuffer`. the buffer only had the `push_*` calls, so a check meant writing the `if` and the push yourself: [src/lib.rs L161-L172](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L161-L172). now `ensure!(errs, cond, tokens => Code)` pushes the code at the tokens when the condition is false, and `ensure!(errs, cond, tokens => Code, ctx)` puts the context after the message: [src/lib.rs L126-L142](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L126-L142). it's an expression that comes back `true` when the rule held, so when a failed check leaves nothing to build from, the caller can skip that item and move on to the next: [src/lib.rs L114-L115](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L114-L115). proof: [tests/codes.rs L43-L53](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/tests/codes.rs#L43-L53), and the doc example runs as a doctest: [src/lib.rs L117-L125](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L117-L125).
- a step that returns `Result` had no way into the buffer except matching on it by hand, since `push` only takes an `Error`, and `?` on it leaves the macro at the first error: [src/lib.rs L155-L160](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L155-L160). now `absorb` takes the result as is. the value comes back as `Some`, the error goes in the buffer and the caller gets `None` and keeps going: [src/lib.rs L221-L231](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L221-L231).
- `finish` gives back only `Result<(), Error>`, so whatever got built had to be returned separately after it: [src/lib.rs L173-L179](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L173-L179). `finish_with(value)` is the single exit now, `Ok(value)` if nothing was pushed, otherwise the folded error: [src/lib.rs L232-L235](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L232-L235). proof for `absorb` and `finish_with`: [tests/codes.rs L55-L63](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/tests/codes.rs#L55-L63).
- `.collect::<Result<Vec<_>, _>>()` stops at the first `Err`, so every error after it never gets reported. `collect_all` runs every step through `absorb` and exits through `finish_with`, so it returns every value or every error together: [src/lib.rs L178-L185](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L178-L185). proof: two errors mixed in with good values, both come back, in order: [tests/codes.rs L65-L78](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/tests/codes.rs#L65-L78).
- `push` had no doc, so nothing said what happens to the same error pushed twice or to an error that already has others combined into it: [src/lib.rs L155-L160](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L155-L160). the doc says it now. every error folded into `e` comes with it, nothing gets merged, and the compiler itself shows an identical message at an identical place once: [src/lib.rs L201-L203](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L201-L203). proof: the same code pushed twice plus an already combined error, and all four come back: [tests/codes.rs L80-L92](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/tests/codes.rs#L80-L92).
- the list at the top of lib.rs now names `ensure!` and `collect_all` next to `SynBuffer` and the `err_*` helpers: [src/lib.rs L11-L12](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L11-L12) is now [src/lib.rs L11-L14](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L11-L14).

### the codes table

- the duplicate code check in `liaise_codes!` was an associated const, `_UNIQUE`, inside `impl $name`: [src/lib.rs L88-L92](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L88-L92), and the only thing touching it was `let _ = Self::_UNIQUE;` in `code_id`: [src/lib.rs L96-L97](https://github.com/jameshuntt/liaise_proc_macro/blob/e1ba9198b6e39edcec67a278a20c76964068d8ba/src/lib.rs#L96-L97). that only got evaluated at codegen, so `cargo check` passed a table with a duplicate code and it only failed at build. now it's a free `const _: () = $crate::__assert_unique_codes($name::ALL_CODES);` next to the impl, and `cargo check` evaluates that too: [src/lib.rs L95-L96](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L95-L96). `code_id` is back to just the match: [src/lib.rs L100-L102](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L100-L102). there's no test for this one in this release.

### CI

- there was no CI before. `.github/workflows/ci.yml` is new: every push and pull request, [.github/workflows/ci.yml L7-L9](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L7-L9), runs `cargo test --all-features` on stable and on 1.85 (the `rust-version` floor), with fail-fast off so one toolchain failing doesn't cancel the other: [.github/workflows/ci.yml L18-L35](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L18-L35).
- publish only runs on a push to main, only after the tests pass, and one at a time (`concurrency: publish`): [.github/workflows/ci.yml L37-L41](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L37-L41). it's crates.io trusted publishing, `id-token: write` on that job plus `rust-lang/crates-io-auth-action`, so there's no stored token: [.github/workflows/ci.yml L42-L44](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L42-L44), [.github/workflows/ci.yml L58-L64](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L58-L64). the rest of the workflow is `contents: read`: [.github/workflows/ci.yml L11-L12](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L11-L12).
- before publishing it asks the crates.io API whether this name and version are already up. 200 skips, 404 publishes, anything else fails the job: [.github/workflows/ci.yml L48-L57](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L48-L57).
- the publish step stops if anything besides `Cargo.lock` is uncommitted (it can differ when a sibling crate is cloned next to this one), so the `--allow-dirty` on `cargo publish` only ever covers `Cargo.lock`: [.github/workflows/ci.yml L66-L71](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L66-L71), [.github/workflows/ci.yml L76-L76](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L76-L76).
- crates released together publish in dependency order, so when `cargo publish` fails because a dependency isn't on crates.io yet, it waits 30s and tries again, 30 attempts in all. any other failure exits right away: [.github/workflows/ci.yml L72-L82](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/.github/workflows/ci.yml#L72-L82).
